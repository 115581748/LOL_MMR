# 峡谷天平

> 新增：Riot API 高分段英雄/位置行为参数模型，见 [MODEL_README.md](MODEL_README.md)。

一个用动态机制图解释《英雄联盟》排位系统中 MMR、Rank、LP、匹配与常见 Elo 叙事的中文单页网站。

直接打开 `index.html` 即可浏览，无需安装依赖。

## 本地赛后对比助手

直接双击 `release/LOLHighRankComparator.exe`。这是 Python/Tkinter 原生 Windows 程序，不需要浏览器或本地网站。顶部可以随时输入 `玩家名#TAG`（也接受 OP.GG 玩家链接）并更换 Riot API Key；Key 只保存在 `%LOCALAPPDATA%\LOLHighRankComparator\riot_api_key.txt`。

程序每 1 分钟检查一次最近的单双排比赛。检测到新比赛后会更新逐局数据，并为每场比赛保存 Match-v5 Timeline 复盘。`整场小地图` 页使用 Riot 官方 Data Dragon 图标显示英雄、装备和召唤师技能；人物坐标采用 Timeline 约 60 秒一次的真实采样，击杀、塔、龙、龙魂、水晶等事件使用原始毫秒时间戳，控制条可按秒拖动。地图下方的双队 TAB 面板会重建所选时刻的等级、K/D/A、补刀、经济和装备。

发生英雄击杀后，地图头像会移动到 Riot 击杀事件记录的死亡地点，并以灰色遮罩、叉号和死亡倒计时标记；下方 TAB 头像同步显示阵亡状态。死亡时间和地点是事件事实，普通 Timeline 没有精确复活事件，因此倒计时始终写作“预计”，只用于复盘界面，不进入模型指标。

`事件`图层会把每组三次及以上、相邻击杀不超过 15 秒的连续英雄击杀聚类为一场团战，显示时间范围、双方击杀比、参与人数、位置与置信度；该团战始终标注为规则识别的派生事件。`原因`图层会将团战失利、近期阵亡、目标区人数、距离、购物、视野动作、团队经济与跨图交换组织成“证据 → 候选原因 → 丢龙/先锋”的证据图，不把时间先后冒充确定因果。

Riot API 不提供小兵实时坐标。地图上的三路兵线图标依据召唤峡谷公开出生规则（1:05 首波、随后每 30 秒）、标准路线与移动速度推算，并在界面和悬停提示中明确标注为估算；它不能反映真实清线、控线或推线结果。Timeline 只能在比赛结束后取得，因此整个功能是赛后复盘，不是进行中对局的实时地图。

逐局表同时展示“你的本局值 / 同位置对手本局值 / 你的英雄 D4+ 基准 / 对手英雄 D4+ 基准”，并给出直接对位差和双方各自相对基准的差值。25 分钟后的英雄伤害与承伤按实际 25+ 游戏时长折算为每分钟，0–15 与 15–25 分钟指标不变。

Development Key 过期后，直接在 EXE 顶部粘贴新 Key 并点击“应用输入并刷新”。Key 不会编译进 EXE，也不会写入公开模型数据。

峡谷交互模型使用 Riot Data Dragon 16.12.1 的英雄头像、小地图和召唤师技能图标。`assets/rift-atmosphere.png` 为本项目生成的氛围图。

## 内容边界

- Riot 官方材料用于确认 MMR、Rank 与 LP 的公开机制。
- Glicko、TrueSkill2、Elo-MMR 论文只用于解释现代评分系统的一般思想，不声称 Riot 使用这些具体算法。
- 本项目并非 Riot Games 官方项目。Riot Games 及《英雄联盟》相关素材归其各自权利人所有，使用时应遵守 Riot 的玩家内容政策。
